根据需求初稿中的预设角色和核心功能模块，为了保证逻辑清晰且符合 React 前端开发的常规路由设计，系统大致需要 **3 个主页面（对应三个角色的工作台）** 和 **2 个表单/详情视图（可做成独立页面或弹窗）**，外加一个用于切换预设账号的辅助组件。

以下是具体的页面规划建议：

### 1. 辅助页面/全局组件（由于跳过了真实登录）
*   **模拟登录/角色切换栏 (Mock Login/Role Switcher)**：
    由于系统不包含真实的用户注册和登录模块，但在测试时需要在 5 个预设账号（3 个员工、1 个经理、1 个管理员）之间切换以验证越权访问拦截和不同视图。建议在前端顶部导航栏做一个下拉菜单，直接切换当前登录人。

### 2. 普通员工视图 (Employee Pages)
*   **页面一：我的请假台 (My Leave Dashboard)**
    *   **功能**：展示当前员工的“假期余额”（尤其是年假剩余天数）和“请假申请单列表”。
    *   **操作**：列表需支持按状态（草稿、待审批、已批准等）筛选；提供“新建请假申请”按钮；对列表中的草稿状态提供“编辑”和“删除”按钮，对待审批状态提供“撤回”按钮。
*   **视图/页面二：请假申请表单页 (Leave Application Form)** *(可做成抽屉 Drawer 或弹窗 Modal)*
    *   **功能**：用于新建或编辑请假单（草稿或被打回状态下）。
    *   **核心内容**：包含请假类型、起止时间、时长、原因等字段。
    *   **交互要求**：选择“年假”时，需要触发前端实时校验，如果计算出的时长大于剩余天数，需实时报错并禁用提交按钮。

### 3. 经理视图 (Manager Pages)
*   **页面三：审批中心 (Approval Center)**
    *   **功能**：经理的工作台，列表展示权限范围内的请假单。
    *   **操作**：分为“待我审批”和“我已处理”两个 Tab 页。点击待审批记录可进入审批操作。
*   **视图/页面四：审批详情与操作页 (Approval Detail)** *(建议做成弹窗或右侧抽屉)*
    *   **功能**：展示员工请假单的具体信息（只读）。
    *   **核心内容**：包含“审批意见”输入框（必填），以及“审批通过”和“打回”两个操作按钮。

### 4. 系统管理员视图 (Admin Pages)
*   **页面五：假期额度管理台 (Leave Quota Dashboard)**
    *   **功能**：列表展示所有员工的当前假期余额。系统管理员在此页面无法查看具体的请假单明细。
    *   **操作**：针对指定员工，点击“调整额度”按钮，弹出一个小表单（输入假期类型、增减天数/最新总额），用于手动设置或调整假期总额度。

### 总结
在 React 路由 (React Router) 设计上，你实际只需要配置 **3 个主路由**：
1.  `/employee/dashboard` （普通员工请假台）
2.  `/manager/approvals` （经理审批中心）
3.  `/admin/quotas` （管理员额度管理台）

至于新建请假、审批操作、调整额度等动作，考虑到内容不多，强烈建议使用 **弹窗 (Modal) 或 抽屉 (Drawer)** 来实现，这样可以减少页面跳转，让 GitHub Copilot 在生成前端组件时更加聚焦于同一个组件文件内的状态流转（State Management）。
