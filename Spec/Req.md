### 请假申请管理系统：需求规格说明 (含预设角色版)

#### 0. 预设账号与角色权限 (Mock/硬编码用户)
系统不包含用户注册、登录、信息维护等模块，直接在底层/数据库中预设 **5 个测试账号**。
*   **普通员工 (3名)**：
    *   权限：只能提交请假单、编辑/删除自己的草稿、撤回审批中的申请、查看自己的请假记录和假期余额。
*   **经理 (1名)**：
    *   权限：负责审批流转，可以查看所有待审批和已处理的请假单，执行“审批通过”或“打回”操作，并填写审批意见。
*   **系统管理员 (1名)**：
    *   权限：负责系统底层配置与额度管理，可以查看所有员工的假期余额，并能手动设置或调整员工的年假等假期总额度。不参与审批流程。

#### A. 核心功能模块
1.  **请假申请单管理 (CRUD)**：
    *   **申请**：员工填写请假单。
    *   **编辑**：仅允许普通员工在“草稿”或“被打回”状态下修改。
    *   **删除**：仅允许普通员工删除“草稿”状态的申请。
    *   **查询列表**：普通员工看自己的；经理看权限范围内提交的（待审批、已处理）；系统管理员无权查看或干涉具体请假单细节。
2.  **审批流转 (由经理执行)**：
    *   **提交**：员工操作，进入待审批状态。
    *   **审批通过/打回**：经理专属操作，必须填写审批意见。
    *   **撤回**：员工在经理审批完成前可自主撤回。
3.  **假期额度管理与查询**：
    *   **余额调整 (管理员专属)**：系统管理员可查看所有人的余额，并可以设置、调整指定员工的各项假期总额度。
    *   **余额查询 (普通员工)**：普通员工仅能查询自己的剩余假期。

#### B. 数据字段与基础校验规范
| 字段名 | 类型 | 校验规则 | 备注 |
| ------ | ------ | ------ | ------ |
| **请假类型** | 枚举 | 必填 | 年假、病假、事假、调休 |
| **开始/结束时间**| DateTime | 必填 | 结束必须晚于开始，开始不能早于当前时间 |
| **时长** | Decimal | 自动计算 | 单位：天 (最小 0.5 天) |
| **请假原因** | String | 必填 | 最小 10 个字符，最大 500 字 |
| **当前状态** | Enum | 系统控制 | 草稿、待审批、已批准、已打回、已撤销 |

#### C. 业务规则与进阶校验 (Business Rules)
1.  **假期额度双端校验 (年假专项)**：
    *   **前端实时拦截**：当员工请“年假”时，系统检查其剩余天数。若请假天数 > 剩余天数，前端实时报错提示“额度不足”，禁用提交按钮。
    *   **后端安全校验**：后端 Web API 接收请求时二次独立调用额度检查服务校验，超出额度则直接拦截并返回业务级错误。
2.  **越权访问拦截 (RBAC)**：
    *   后端接口需严格校验调用者角色：员工不可调用审批接口，经理和员工不可调用额度调整接口。

#### D. 业务流程逻辑 (Workflow)
*   **状态转换规则**：
    *   **Draft -> Pending**: 员工提交操作。
    *   **Pending -> Approved**: 经理同意。
    *   **Pending -> Rejected**: 经理不同意。
    *   **Pending -> Cancelled**: 员工自主撤销。
    *   **Rejected -> Draft**: 经理打回后回到草稿状态，员工可重新编辑。
